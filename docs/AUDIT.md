# Code and third-party material audit

Review of the files tracked by the project. Goal: the module, HUD, stamina, app and installer are original work, and no
game material is redistributed nor third-party trademarks used in the product.

## Summary

| Item | Origin | Redistributed? | Status |
|---|---|---|---|
| `core/`, `features/stamina/`, `features/songbook/`, `features/button_mapping/`, `features/probe/` | Original | Yes (compiled module) | OK |
| `app/` (window, profiles, installer, texts) | Original | Yes | OK |
| `tools/` (build, tests, analysis) | Original, except the listed dependencies | No | OK |
| Switch / PlayStation / Xbox button textures | Original | Yes | Drawn in code by `tools/make_buttons.py` |
| CityHash64 algorithm | Public Google algorithm | Only the code that implements it | Own implementation; no Google code copied |
| Game code and materials | Original game | No | Only read from the user's dump at runtime |
| Development tools (LLVM, PyInstaller, lz4, zbic, devtool, emulator) | Third parties | No | Development dependencies, not part of the product |

## Original code

- `core/`: MOD0 header, hooks, dispatch, HID, configuration, player/enemy tracking and HUD.
- `features/stamina/`: stamina state machine and input/speed hooks. The values in `stamina_default_config()` are own
  settings, not a copy from another mod.
- `features/songbook/`: playback from the native songbook. Own implementation based on the ocarina context fields and
  on injecting the five note buttons; it uses no third-party code.
- `app/`: Tkinter window, complete profiles, installer, cross-platform paths and texts in six languages.
- `tools/`: build, live-test, dump and analysis scripts. Some read the game or use the debug server, but they are not
  packaged with the app.

No source code from another mod has been found inside `core/`, `features/` or `app/`.

## Button mapping

The button mapping (assignable B, L, R and ZR) is original work. The button textures are generated by
`tools/make_buttons.py` from shapes and text (three styles: Switch, PlayStation and Xbox) and installed as romfs.
No third-party mod is downloaded or bundled.

## CityHash64

The game engine stores a 64-bit hash next to each pane name. `tools/lib/cityhash.py` implements the public CityHash64
algorithm to compute those hashes; it contains no Google code, only the own implementation of the published constants
and operations. It is used at build time to generate `hud_names.h`.

## Game material

- `build/`, `data/`, `release/` and `app/payload/` are ignored by git.
- `tools/check_no_game_data.py` walks the git index and fails if it finds dump extensions (`.byml`, `.bgyml`, `.bntx`,
  `.sarc`, `.nso`, `.nro`, `.ips`, etc.), `romfs/`/`exefs/`/`app/payload/` folders or files with game format magic.
  It can be run before each commit.
- The repository contains no textures, layouts, BYML, romfs, `main` or any file extracted from the game.
- `tools/make_romfs_opts.py` generates the optional romfs from the user's dump; the app copies that result only if the
  user enables the option.
- `tools/make_enemy_opts.py` generates the two beta enemy mods (duplication and speed) from the dump; they are not
  versioned or redistributed either.
- The module uses internal game resource names (for example `Circle64_00`, `NumBaseSide_00`, `Nt_RupeeIconNew_00`) to
  draw the HUD with the native look. They are references to files already present in the user's game, not
  redistributed material.
- Own pane names were renamed from `*_Oot*` to `*_Shb*` to avoid the game's abbreviation.

## Texts and trademarks

The versioned files and the app texts were reviewed:

- No textual references to the franchise, the console or the game's region remain in the product. The three-triangle
  emblem in the header is drawn in code (three polygons) and uses no official asset or logo.
- The protagonist's name was replaced with "the player" in comments and documentation; internal identifiers changed
  from `g_link_*` to `g_player_*`.
- "Hero Mode" is kept as a generic difficulty name (it is the term used by the product itself).
- The `OoT` abbreviation was removed from the code and the pane names.

## Development dependencies

They are not distributed, but they should be documented:

- LLVM/clang/lld (llvm-mingw) to compile the module.
- PyInstaller to package the app.
- `lz4` and `zbic` to decompress the original `main` during verification.
- The debug server client and the BYML/GameData readers used by the test scripts.

## Pending decision

The project has no `LICENSE` file. If it is going to be published, a licence should be chosen for the original code
(for example MIT). This audit does not decide the licence; it only records what is original and what is third-party.
